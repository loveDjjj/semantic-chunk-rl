# 方法

模型有两个角色：Qwen3.5-4B planner 把文字写成有限的语义段和每段的 chunk 数，LongLive-1.3B executor 按计划生成视频。每段允许 1、2、4、6 个 chunk，最多 5 段、总计不超过 30 个。联合 RL 指两套策略都更新；段内联合去噪是视频生成时的分组方式，两者互不等价。

## 我们要检验什么

**同一个决定能否同时服务语义规划和视频生成：Planner 为一个事件选择几个 chunk，这个数既决定提示词何时切换，又决定 Executor 在一次去噪中共同处理多长的视频。** 评价标准不是计划写得像不像教师，而是：在相同视频时长和可比计算预算下，动作是否真的出现、顺序是否正确、跨段是否连贯，同时不牺牲画质。

给定原始提示词 $x$，计划是 $P=((c_1,n_1),\ldots,(c_J,n_J))$。$c_j$ 是第 $j$ 段的可视描述，$n_j$ 是以 LongLive 原生 chunk 为单位的整数。比如“一个人拿起杯子，倒入茶，再放回杯子”：一种待比较的计划是给三个事件分配 $(1,4,1)$，而不是一律 $(2,2,2)$。两者同为 6 个 chunk，比较的是**同样多的帧分给哪些动作**，而不是哪条视频更长。例子不是人工指定的最优边界。

| 哪个决定被改变 | 对应的比较 |
|---|---|
| 是否拆提示词 | 原生 LongLive 使用原 prompt；其他组按计划切换描述。无 Planner 基线要另外匹配总帧数。 |
| 每个事件占多久 | 固定描述和总 chunk 数，比较等跨度、语义选长、打乱同一组段长。当前自由规划只有总预算上限，没有强制各视频等长。 |
| 每次去噪处理多宽 | 固定**完全相同的计划**：`segment-joint` 将段内 $n_j$ 个 chunk 一起去噪；`causal-chunkwise` 保留同一段描述，但一次只去噪一个原生 chunk。$n_j=1$ 时两者的块宽相同。后者是评估对照，不是当前 Executor RL 的训练模式。 |

[LongLive](https://hanlab.mit.edu/projects/longlive) 已支持因果生成中的提示切换和 KV 重缓存。[TempAct §4.1–4.3](https://arxiv.org/html/2606.28016v1) 已有跨度规划、Planner/Executor 联合 RL 和两层组内比较；其描述按给定跨度切换，执行更新聚焦切换后的第一个 chunk。[Flex-Forcing](https://proceedings.mlr.press/v306/ma26b.html) 也已研究灵活分块。因此，**要验证的贡献**是语义选择的 $n_j$ 同时控制时间分配与段内去噪组宽，以及怎样从视频回报训练这个决定。不是首次做分段、双策略 RL 或可变块宽；SFT 是学习这种动作格式的起点，也不是核心创新。

## 第一阶段：SFT

选取静态场景、单动作、有顺序的多动作和明确转场；教师不得凭空添加事件。输出为 `[{"step_index":0,"prompt":"A cyclist brakes to a stop.","num_chunks":2}]`。审核动作覆盖、顺序、冗余和时长，允许简单场景只写一段。模型生成的 `review.jsonl` 默认未经批准；审核人签名后才能构成 SFT 样本。同一审核分组不跨训练集和验证集；导出程序按归一化后的 prompt 和组名排除显式指定的留出集，不做自动语义查重。SFT 数据清单记录教师与模板，进入 RL 前再独立核验清单和训练所得 adapter 的摘要。

本轮从 VBench / VBench-Long 共享的官方标准提示词池选 600 条，从 RL 语料选 1,400 条。官方原句是有意纳入的训练来源，实际进入审核导出的官方条数记录在 `official_training_prompt_count`；该数覆盖训练和内部验证两个 split，并非独立测试题数。报告该模型的官方整套 VBench 分数时须标注与教师语料重合，不将它解释为完全未见提示词上的泛化成绩。

历史 4B 的 SFT 是旧 RL 四个候选、相同四个 seed 的奖励赢家蒸馏，不是 GPT 教师数据。其验证记录显示格式有效由 236/247 到 247/247；混合长度由 218 条降至 114 条，验证伪标签本身只有 98 条。接近标签分布不代表画质提升。

## 第二阶段：当前整计划训练

[24 卡配方](../configs/rl-whole24.json)使用 `whole-plan-v1`。Planner 从教师 SFT 的 4B adapter 开始，Executor 从已核验的 LongLive 策略 adapter 开始；教师不参与 RL 打分。

1. **采完整计划。** 对同一个原始 prompt，在相同段数和 chunk 预算上限下独立采四次。每次决定整份计划的描述和时长，可以采出相同方案，不重抽到不同为止。四份计划使用同一组四个视频 seed，共 16 个逻辑结果。完全相同的计划和 seed 可复用成片和评分，但仍保留原来的采样次数。
2. **对整片计算两项分数。** 先从原始 prompt 提取共同的必要事件和明示顺序，不因候选计划省略一个事件而降低要求。用采样帧核验事件是否完成；有明示顺序时，还要核验完成帧是否严格有序。记完成率为 $C$、顺序满足率为 $O$。无显式顺序时 $S=C$，否则 $S=0.6C+0.4O$。证据不足且重判仍无法确认时，不当作零分。质量 $Q$ 汇总整片的成像质量（25%）、美学（20%）、外观一致性（15%）、运动平滑度（15%）、动态表现（15%）和物理合理性（10%）。
3. **同分数，不同对照组。** Planner 和 Executor 都取 $R=(S+Q)/2$，不再加局部或边界项。例如 $S=0.60$、$Q=0.75$ 时，两端都拿 0.675。Planner 先对各计划的四次执行求平均，再在同一 prompt 的四次计划采样间计算相对优势；相同计划合并估分后按原频次计入。Executor 固定计划，在四个执行 seed 之间计算优势。打平不强分胜负。质量在语义打平时仍能拉开回报，因此优势不能直接解释为分段更准确。

[采样](../src/models/planner.py) · [事件证据](../src/models/scoring/events.py) · [回报合成](../src/rl/reward.py) · [优势计算](../src/rl/objectives.py)。这套训练比较的是**整份方案**。各候选可能有不同总帧数；要识别段长本身的因果影响，须另做等时长、固定描述和计算预算的对照。

## 独立评估

训练奖励不是 VBench 分数。项目的[评估配方](../configs/vbench.json)固定 Planner 和视频的种子；本地 Planner 按约束随机采样（`do_sample=True`、温度 1、`top_p=1`），不是贪心解码。做去噪方式的成对对照时应复用同一份 plan 和相同视频 seed。固定种子不保证不同软件、硬件或外部 API 逐位重现。评测推理默认每卡单个 Planner 实例，一次前向处理最多 16 个提示词（`SCRL_EVAL_PLANNER_BATCH_SIZE=1` 用于调试）。每行的随机数按自己的任务种子推进，使用自己的语法状态、可选 token 和 EOS；不同提示词不因此共享计划或相互竞争。T5 文本 batch 8 和 LongLive 视频 batch 2 是独立的后续优化；后一项仅对完整段长序列相同的任务配对。这里的 batch 是推理调度，不改变联合 RL 的候选数、采样协议或优势分组。当前教师 SFT + 4B 整计划联合 RL 没有可报告的 VBench 实测点；[历史结果](history/vbench-results-through-20261125.md)不能替代它。

## 历史对照：四格配方

以下采样、局部奖励和字段优势仅适用于 [rl.json](../configs/rl.json) 的 `crossed-2x2-v1`，不用于上述整计划训练。

1. 从审核过的教师 SFT adapter 初始化 4B Planner，从独立核验的 LongLive 策略 adapter 初始化 Executor，各保留一份参考策略用于 KL 约束。教师不在 RL 环路中投票，也不为视频打分。
2. 在同一个原始 prompt 上采一份锚点计划，均匀抽目标段 $j$。固定公共前缀、其他段的文字和事件顺序。Planner 为第 $j$ 段采两次描述；在同一个锚点描述条件下再采两次时长分配。只在第 $j$ 段和下一段之间转移 chunk：两段之和、其余段长、整片帧数均不变。例如 $(2,4,2)$ 与 $(4,2,2)$，不是两条不同长度的视频。
3. 将两个描述和两个分配交叉，而不是重新采四个独立后缀。四格共享**同一组**执行 seed、相同的视觉前缀及 Executor 快照。噪声按 seed、去噪阶段和绝对帧号对齐；相同帧号并不保证在时长不同的计划里属于同一事件。

| 目标段描述 | 分配 A | 分配 B |
|---|---|---|
| X | c0：seed 1、2、3、4 | c1：同四个 seed |
| Y | c2：同四个 seed | c3：同四个 seed |

四格配方每条 prompt 是 **2 时长 × 2 描述 × 4 seed = 16 个逻辑结果**。每条实际生成的视频只提交一次评分，整片和局部证据同时供两端使用。默认复用完全相同的计划与 seed 的执行。两轴均按策略有放回采样，不为凑不同答案而拒绝采样。抽到末段（含单段）时不向前挪动公共前缀；只有一种合法分配、两次分配相同或两次描述相同时，对应轴不产生更新。[采样实现](../src/models/planner.py) · [训练入口](../src/runtime/worker.py) · [批次组装](../src/rl/rollout.py) · [配方](../configs/rl.json)

### 四格配方的回报

以下是四格配方的事件奖励 `event-v2`。所有分量均在 $[0,1]$，不是 VBench 百分点；权重是配方选择，不是实验结论。

**1. 从原始要求确定评分项。** 视频裁判先只看原始 prompt，提取可核验的必要事件、原文明示的先后关系与切镜。静态 prompt 评实体、属性和关系，不强造动作。四格使用同一张事件表；不能因 Planner 省略事件而缩小全局分母。局部归属在看视觉证据之前按各段描述决定：同一事件至多归一段完成，未归属也仍须参加全局评分。见[事件裁判](../src/models/scoring/events.py)。

**2. 用帧证据计算任务分。** 对整片和目标段分别抽帧，默认每个视野最多 16 帧。完成必须有实际抽到的帧号和可见结果；有反证或明确遗漏记未完成，证据不足则改用另一组采样帧再判一次。仍无法判断的评分报错，不当成零分训练。令 $C$ 为已完成必要事件数除以全部必要事件数；$O$ 为满足的显式先后关系数除以全部显式关系数。两端事件都完成且首次证明完成的采样帧严格有序，才算满足一条关系。没有顺序要求时只使用 $C$：

$$
T=\begin{cases}0.6C+0.4O,&\text{有显式顺序},\\ C,&\text{否则}.\end{cases}
$$

**3. 质量只在任务分基础上调节回报。** 整片和目标段分别得到质量分：

$$
Q=0.25I+0.20H+0.15C_{\rm vis}+0.15M+0.15D+0.10F .
$$

六项依次为 MUSIQ 成像质量、美学、CLIP 外观一致性、AMT 运动平滑度、符合原要求的动态表现、物理合理性。有运动要求时光流覆盖度辅助判断动态表现，不以运动越多为越好。[视觉代理](../src/models/scoring/models.py) · [评分服务](../src/models/scoring/service.py)

整片质量为 $Q_g$；Planner 回报为：

$$
R_P=T(0.8+0.2Q_g).
$$

目标段的局部任务分 $T_j$ 是**归该段负责**的事件在段内的完成率，不拿相邻段的完成帧重复计分。对期望连续的内部入口或出口，用边界两侧的 CLIP 外观连续性与光流运动连续性各占一半，适用边界取均值得 $B_j$；源 prompt 明确要求且归属到该边界的切镜不扣连续性分。记段内质量为 $Q_j$：

$$
Q_j^*=\begin{cases}0.8Q_j+0.2B_j,&\text{有适用边界},\\Q_j,&\text{否则}.\end{cases}
\qquad
L_j=\begin{cases}T_j(0.7+0.3Q_j^*),&\text{有归属事件},\\R_P,&\text{无归属事件}.\end{cases}
$$

$$
R_E=0.7L_j+0.3R_P .
$$

例如原 prompt 要求三个事件且有两条显式顺序，只完成两件、满足一条顺序，则 $T=0.6(2/3)+0.4(1/2)=0.60$。若 $Q_g=0.75$，则 $R_P=0.57$。若目标段完成其唯一事件、$Q_j=0.80$ 且 $B_j=0.60$，则 $Q_j^*=0.76$、$L_j=0.928$、$R_E=0.8206$。过渡段若不负责任何可核验事件，则 $R_E=R_P$。没有段数奖励、总长度奖励或匹配教师段长的奖励；KL 只进入损失。旧 `quality-first-v1` 是独立对照，不允许用其断点直接续训这一配方。[回报实现](../src/rl/reward.py)

### 四格配方的字段优势

设 $a$ 为描述行、$b$ 为时长列、$s$ 为执行 seed。先求每格的 Planner 平均回报 $h_{ab}=M^{-1}\sum_s R^P_{abs}$。下面的 $Z$ 表示**只在指定比较组内**中心化、除以总体标准差（下限 0.02），再裁剪到 $[-3,3]$。

| 更新对象 | 比较与优势 | 哪些参数获得这个信号 |
|---|---|---|
| Planner 描述 | 对列取均值，再比较两行：$A^c_a=Z_a((h_{a0}+h_{a1})/2)$ | 仅目标段的描述 token |
| Planner 时长 | 对行取均值，再比较两列：$A^n_b=Z_b((h_{0b}+h_{1b})/2)$ | 仅选择目标段 chunk 数的动作；相邻段以剩余预算确定，不重复计梯度 |
| Executor | 固定完整计划，在一个格子内计算 $A^E_{abs}=Z_s(R^E_{abs})$ | 仅回放该视频目标段的随机去噪转移 |

这些比较只在同一 prompt、同一目标段和同一策略版本内进行。任一轴的配对平均差打平，该轴没有更新；即使存在“X 配 A 好、Y 配 B 好”的交互，两轴平均效应都为零时也不硬造梯度。每轮 `report.json` 中的 `planner_field_advantages` 记录每格两项优势。旧 `candidate-v1` 和 `focal-mean-v1` 仍可读取，但使用不同归因，也不是这一四格对照。

Planner 在对应字段的采样条件和合法 token 集合上回放旧、新、参考策略概率。描述和时长默认各占一半，按字段内 token 平均；PPO 裁剪范围为 $1\pm0.2$，参考策略 KL 系数为 0.01。Executor 使用 $-A^E\log(p_\theta/p_{\rm old})$ 型损失和高斯 KL，按目标段时长占比和抽样概率加权。两端在同一批次边界提交，不保证两端每批都有非零梯度。[优势计算](../src/rl/objectives.py) · [Planner 优化](../src/models/verl_policy.py) · [Executor 回放](../src/models/executor.py) · [训练循环](../src/rl/train.py)

## 解释结果的限制

| 可能的问题 | 为什么影响结论 | 怎样验证 |
|---|---|---|
| 漏掉短事件或判错先后 | 裁判可能漏列原文要求，稀疏采帧也可能让两个事件首次出现在同一帧。可核验的时间分辨率限制了顺序分。 | 用只改顺序、删事件、保持静态的人工配对检验排序；分别报告无法评分、顺序并列与总分。 |
| 四格配方的配对主效应抵消 | 某一描述只适合某一时长时，两轴的边际均值可能都打平。末段或预算不可移动的样本不提供时长对照。 | 按目标位置报告有不同时长的组占比、两轴零优势率与四格原始分，而不仅报均值。 |
| 四格配方错误豁免或惩罚边界 | 裁判可能把原文要求的切镜映射到错误边界；连续性代理也不等于自然度。 | 区分连续动作与显式转场，检查原文引文、归属边界和人工盲评；对照关闭边界项后的排序。 |
| 大 Planner、更长的视频或更多计算也能改善分数 | 跨模型总分既不是边界机制的效果，也不是联合 RL 的效果。相同 seed 不会自动对齐不同时长的语义事件。 | 先固定 4B、Executor、prompt、帧数、seed；记录实际耗时和算力。先比较等跨度/语义选长/乱序段长，再固定计划比较段内联合与逐 chunk。 |
| 模型确实更新，不等于奖励方向正确 | KL、回报和独立评估是三种不同量；训练分上升不能证明留出集受益。 | 从同一教师 SFT step 0 出发做冻结两端、仅 Planner、仅 Executor、联合更新四组；同预算报告两端参数变化、独立动作指标、VBench 质量/语义/总分和按 prompt 配对的区间。四组是建议对照，不代表现有主入口已支持全部模式。 |

**证据边界。** 历史 4B 仅训 Planner 的 576 组中，218 组候选平均语义分完全并列，120 组相同目标动作出现相反符号优势。这是采用同目标聚合的动机，不能证明新归因有效。在同计划、同 seed 的去噪对照里，旧 1.7B 参考和 CK250 的段内联合相对逐 chunk 分别高约 1.07、1.11 个 VBench 总分百分点；9B 和两组 GPT 的区间跨零，4B 缺少估计区间所需的明细。这只说明**执行方式在部分组合里有影响**，还不能证明语义边界优于等跨度，更不是“新教师 SFT + 4B 联合 RL”已经获益。[结果与比较口径](history/vbench-results-through-20261125.md)
